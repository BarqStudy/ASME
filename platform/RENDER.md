# تشغيل منصة ASME على Render

هذا الدليل يشغّل النسخة الكاملة من التطبيق وقاعدة البيانات. ملف `render.yaml` في جذر المستودع يربطهما تلقائيًا ويضيف قرصًا دائمًا للمرفقات. لا ينشئ الملف حسابًا لدى Render أو يشغّل خدمات بمجرد إضافته إلى GitHub.

**القالب يقترح استضافة وقاعدة بيانات وقرصًا مدفوعة. راجع التكلفة التي يعرضها Render قبل اعتماد الإنشاء.** لا توجد كلمات مرور أو مفاتيح بريد محفوظة داخل القالب.

## 1. إنشاء الحساب وربط GitHub

1. افتح <https://render.com> واختر **Get Started** ثم التسجيل بواسطة **GitHub**.
2. استخدم الحساب الذي يملك `BarqStudy/ASME` أو يملك صلاحية إدارة المستودع.
3. إذا ظهرت صفحة صلاحيات GitHub، امنح تطبيق Render الوصول إلى مستودع `ASME`؛ لا تحتاج إلى منح الوصول لبقية المستودعات.

## 2. إنشاء التطبيق وقاعدة البيانات

افتح [رابط نشر ASME](https://render.com/deploy?repo=https://github.com/BarqStudy/ASME)، أو اختر **New → Blueprint** من لوحة Render واربط المستودع `BarqStudy/ASME` على فرع `main`.

سيقرأ Render ملف `render.yaml` من جذر المستودع ويعرض:

| المورد         | وظيفته                                                   |
| -------------- | -------------------------------------------------------- |
| `asme-nu`      | تطبيق Node.js الذي يشغّل الواجهة والحسابات ولوحة الإدارة |
| `asme-db`      | قاعدة PostgreSQL، مرتبطة بالتطبيق داخليًا                |
| `asme-uploads` | قرص دائم بحجم 1 GB للمرفقات على `/var/data`              |

راجع المنطقة والخطط والتكلفة، ثم اعتمد إنشاء الموارد من داخل Render إذا كانت مناسبة لك. لا تختَر **Static Site**؛ الخدمات التي تحفظ البيانات تحتاج التطبيق الكامل.

تجهيز القاعدة وترحيل بنيتها والإعدادات الأساسية يتم تلقائيًا في `preDeployCommand`. التهيئة لا تضيف الفعاليات التجريبية ولا تستبدل إعدادات النادي الموجودة عند إعادة النشر.

انتظر أن تصبح حالة التطبيق سليمة. افتح عنوانه من لوحة Render، ثم جرّب `<عنوان التطبيق>/api/health`؛ يفحص المسار الاتصال الفعلي بقاعدة البيانات. يستخدم التشغيل `RENDER_EXTERNAL_URL` تلقائيًا لضبط روابط البريد والتحقق من مصدر الطلبات؛ لا تحتاج إلى تخمين اسم عنوان `onrender.com` مسبقًا.

## 3. إعداد بريد النادي

من خدمة `asme-nu` افتح **Environment** وأضف بيانات SMTP من بريد النادي أو مزود إرسال معتمد لديك:

| المتغير                | القيمة التي تحصل عليها من مزود البريد      |
| ---------------------- | ------------------------------------------ |
| `SMTP_HOST`            | عنوان خادم الإرسال                         |
| `SMTP_PORT`            | `587` مع STARTTLS أو `465` مع TLS          |
| `SMTP_USER`            | اسم مستخدم SMTP                            |
| `SMTP_PASSWORD`        | كلمة مرور SMTP أو المفتاح المخصص له        |
| `SMTP_FROM`            | عنوان إرسال مصرح به لدى المزود             |
| `ALLOWED_EMAIL_DOMAIN` | نطاق البريد الجامعي الفعلي للطلاب، دون `@` |

`MAIL_MODE=smtp` مضبوط في القالب. لا تستخدم `file` في الإنتاج. أدخل الأسرار داخل إعدادات Render، ولا ترسلها في المحادثة أو تحفظها في المستودع.

تأكد من نطاق **بريد الطلاب** المعتمد قبل إدخاله؛ لم يُفترض نطاق للجامعة داخل الكود. ترك `ALLOWED_EMAIL_DOMAIN` فارغًا يسمح بإنشاء حسابات بأي بريد مؤكد، ولا يُعد تحققًا جامعيًا.

احفظ المتغيرات وأعد تشغيل/نشر الخدمة. جرّب رسالة تأكيد حساب ورسالة استعادة كلمة مرور قبل إعلان بوابة الطلاب. تشغيل التطبيق أو نجاح `/api/health` وحدهما لا يثبتان وصول البريد.

## 4. إنشاء أول حساب مدير

أضف في **Environment** متغيرين مؤقتين:

- `BOOTSTRAP_EMAIL`: بريد حساب مدير النادي.
- `BOOTSTRAP_PASSWORD`: كلمة مرور خاصة قوية بطول 12 حرفًا على الأقل.

بعد وصولهما إلى الخدمة، افتح **Shell** لخدمة التطبيق ونفّذ مرة واحدة:

```bash
npm run bootstrap
```

الأمر ينشئ أول مدير ببريد مؤكد وصلاحية `SUPER_ADMIN`، ويرفض إنشاء مدير إضافي بهذه الطريقة إذا كان هناك مدير بالفعل. لا تنفّذه داخل قاعدة بيانات أخرى.

احذف متغيري الإقلاع من **Environment** بعد النجاح؛ حذفهما لا يحذف حساب المدير. افتح `<عنوان التطبيق>/auth/login`، وسجّل ببريد المدير وكلمة المرور التي اخترتها، ثم افتح `/admin`.

حدّث بريد التواصل وبيانات النادي من الإدارة، وأضف المحتوى المعتمد. اترك تسجيل العضوية مغلقًا إلى أن تكمل تجربة النموذج والإرسال من حساب طالب تجريبي.

## 5. اختبار البوابة قبل الإعلان

1. `/api/health` يعمل، والصفحة والشعار والخطوط تُحمَّل دون مسار `/ASME` القديم.
2. مدير النادي يستطيع تسجيل الدخول وفتح `/admin`.
3. حساب تجريبي يستقبل رسالة التأكيد ويستطيع الدخول واستعادة كلمة المرور.
4. فتح العضوية من لوحة الإدارة يُظهر خيار الانضمام، وإغلاقها يمنع قبول الطلبات.
5. طلب تجريبي يظهر للإدارة، والمرفقات تبقى متاحة بعد إعادة تشغيل الخدمة.

الحسابات الحالية تعتمد البريد وكلمة المرور. يوجد حقل للرقم الجامعي في بيانات الطالب، لكن **استخدامه كاسم دخول والتحقق الرسمي منه ليسا ضمن إعداد الاستضافة**؛ نضيفهما في مرحلة بوابة الطلاب. الربط بدخول الجامعة الموحد يتطلب التنسيق مع الجامعة وتوفير واجهتها الرسمية.

## الدومين والنسخ الاحتياطي

يمكن البدء بعنوان Render دون شراء دومين. عند إضافة دومين خاص من إعدادات الخدمة، اضبط `APP_URL` على أصله الدقيق، مثل `https://club.example.org`، دون مسار أو علامة `/ASME`؛ هذا المثال ليس عنوانًا محجوزًا للنادي.

القرص يحفظ المرفقات بين عمليات النشر، لكنه لا يُغني عن نسخها احتياطيًا. فعّل سياسة نسخ مناسبة لقاعدة البيانات واحتفظ بنسخ مستقلة للمرفقات، ثم اختبر استعادتهما. لا تضع قاعدة الإنتاج ضمن اختبارات التكامل التي تنشئ قواعد اختبار.

يبقى رابط GitHub Pages نسخة عامة مستقلة؛ تعديلات لوحة الإدارة على قاعدة Render لا تظهر فيه تلقائيًا. عند تجهيز النسخة الكاملة، شارك عنوانها مع الطلاب أو اربطها بدومين النادي.
