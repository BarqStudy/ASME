# نشر Engineering Hub

## فصل الموقعين

GitHub Pages في `barqstudy.github.io/ASME/` يقدم موقع Vite السابق. لا يمكنه تشغيل Next.js API أو جلسات الحسابات أو PostgreSQL. لا تُنسخ `platform/.next` إلى Pages. نشر النسخة الجديدة يحتاج مضيف Node/Docker وقاعدة PostgreSQL وبريد SMTP. لا توجد بيانات اعتماد استضافة إنتاجية في هذه الجلسة، ولم يُنقل النطاق أو يُستبدل الموقع العام تلقائيًا.

## متغيرات البيئة

| المتغير | الاستخدام |
|---|---|
| `DATABASE_URL` | اتصال PostgreSQL خاص بالخادم؛ استخدم TLS حسب مزود القاعدة، ولا تعطل فحص الشهادة |
| `APP_URL` | عنوان HTTPS الخارجي الدقيق، للتحقق من Origin وروابط البريد والشهادات |
| `UPLOAD_DIR` | مجلد ملفات دائم خارج الشجرة العامة؛ افتراضيًا `.data/uploads` |
| `SMTP_HOST`, `SMTP_PORT` | خادم البريد؛ 587 مع STARTTLS أو 465 مع TLS |
| `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | بيانات SMTP وعنوان الإرسال المعتمد |
| `MAIL_MODE` | `smtp` للإنتاج؛ `file` للتطوير فقط |
| `ALLOWED_EMAIL_DOMAIN` | نطاق البريد الجامعي المعتمد، اختياري حتى توفره الجامعة |
| `TRUST_PROXY` | اتركه `false` إلا مع وكيل موثوق يمحو X-Forwarded-For الوارد ويكتبه بنفسه |
| `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` | تهيئة حاوية PostgreSQL في Compose |
| `BOOTSTRAP_EMAIL`, `BOOTSTRAP_PASSWORD` | للإقلاع الأول فقط، ثم أزلهما من التشغيل الاعتيادي |

## Docker Compose

1. انسخ `.env.example` إلى `.env` واختَر كلمة قاعدة عشوائية طويلة.
2. غيّر مضيف `DATABASE_URL` إلى `database:5432` داخل Compose، مع كلمة المرور نفسها (URL-encode للمحارف الخاصة). استخدم كلمة قاعدة hex عشوائية لتبسيط الترميز.
3. اضبط `APP_URL=https://your-approved-domain` ومتغيرات SMTP و`MAIL_MODE=smtp`.

```bash
docker compose build
docker compose up -d database
docker compose run --rm migrate
# بيانات المحتوى الأساسية دون عينات:
docker compose run --rm migrate npm run db:seed
# حدد بريد المشرف وكلمة قوية في .env قبل هذا الأمر:
docker compose run --rm migrate npm run bootstrap
docker compose up -d app
```

لا تستخدم كلمة إقلاع مولدة داخل حاوية `--rm`؛ ستُحذف مع الحاوية. للإنتاج حدد كلمة قوية سرية عبر `.env` أو مدير الأسرار، ثم أزل متغيرات الإقلاع بعد نجاح العملية.

المنافذ الخارجية الافتراضية: التطبيق مربوط بـ`127.0.0.1:3000` فقط، وقاعدة البيانات لا تنشر أي منفذ. اربط وكيل HTTPS مثل Caddy/Nginx بالمنفذ المحلي، مع حد جسم طلب 11MB ووقت طلب محدود. مرّر ملفات الارتباط بأمان واضبط origin نفسه في `APP_URL`. تحقق من تطابق ساعة النظام لأن الجلسات والمواعيد تعتمد عليها.

المستخدم داخل صورة التطبيق هو `node` غير الجذر. قاعدة البيانات والملفات لهما volumes مستقلة. لا تحذف volumes عند تحديث الصورة.

في البيئة السحابية المدارة الحالية فقط، ابْنِ باستخدام شهادة الوكيل كسر BuildKit مؤقت:

```bash
docker compose -f compose.yaml -f compose.managed.yaml build
```

لا تضف شهادة الوكيل إلى الصورة أو Git. لا تنسخ `.env` أو `.data` إلى سياق البناء؛ `.dockerignore` يستثنيهما. يجب أن يستخدم خادم SMTP وسيلة ثقة صالحة دون تعطيل التحقق من TLS.

## نشر Node مباشر

```bash
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run build
npm start
```

اضبط المتغيرات من مدير أسرار المضيف، واستخدم عملية مُدارة قابلة لإعادة التشغيل وHTTPS. خزّن المرفقات في قرص دائم؛ التخزين المؤقت للمنصات serverless لا يصلح للإعداد الحالي. يتطلب تخزين S3 تكاملًا إضافيًا لم يُنفّذ بعد.

## التشغيل والنسخ الاحتياطي

- افحص `/api/health`؛ نجاحه يشمل اتصالًا فعليًا بقاعدة البيانات.
- خذ نسخًا دورية مشفرة من PostgreSQL وvolume الملفات معًا، واختبر الاستعادة في بيئة مستقلة.
- راجع سجل العمليات وإخفاقات البريد. لا تسجل رموز الجلسات أو روابط استعادة كلمات المرور.
- أزل الفعاليات التوضيحية أو حوّلها لمسودات قبل إعلان الإطلاق.
- حدّد نطاق الجامعة ومدة الاحتفاظ بالبيانات ومسار طلبات الخصوصية مع مسؤول النادي.
- راجع [الأجزاء المتبقية](IMPLEMENTATION.md#remaining) قبل وصف الخدمة بأنها مكتملة إنتاجيًا.

اختبار الكاميرا يحتاج HTTPS ودعم BarcodeDetector في المتصفح؛ يوجد إدخال يدوي للرمز كبديل وظيفي. لم تُختبر كاميرا هاتف حقيقية أو تسليم SMTP خارجي لعدم توفرهما هنا.
