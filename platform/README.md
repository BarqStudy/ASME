# ASME NU — Engineering Hub

منصة Next.js فعلية لنادي الهندسة الميكانيكية بجامعة نجران. هذه هي النسخة التي تستخدم خادمًا وقاعدة بيانات؛ موقع Vite السابق في المجلد الأعلى ما زال مستقلًا ويُنشر على GitHub Pages.

**الحالة:** شريحة عملية واسعة قابلة للتشغيل والاختبار محليًا، وليست إعلانًا بأن كل بنود النطاق الكبير انتهت أو أن الخدمة منشورة إنتاجيًا. اقرأ [IMPLEMENTATION.md](IMPLEMENTATION.md) للوظائف المتحققة والأجزاء المتبقية.

## المتطلبات

- Node.js 24 LTS وnpm 11.
- PostgreSQL 18 (أو Docker).
- خادم Node.js + HTTPS + تخزين دائم للملفات عند النشر.
- SMTP فعلي في الإنتاج. صندوق ملفات خاص متاح للتطوير فقط.

## تشغيل محلي

```bash
cd platform
cp .env.example .env
# حرّر .env، واختر كلمة مرور عشوائية قوية، واضبط DATABASE_URL لقاعدة محلية.
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

افتح التطبيق على المنفذ 3000. قاعدة التطوير في البيئة السحابية الحالية تستمع محليًا على 55432، مع بيانات اعتماد عشوائية في `.env` المستثنى من Git. لا تنقل هذا الملف للمستودع.

لتفعيل بيانات عرض موسومة بوضوح:

```bash
SEED_SAMPLES=true npm run db:seed
```

البذر لا يستبدل المحتوى الموجود. التسجيل في العضوية مغلق افتراضيًا. لا تُنشأ حسابات طلاب أو أسماء قيادة أو أعداد عضوية وهمية.

## إنشاء أول مشرف

ضع `BOOTSTRAP_EMAIL` في `.env` ثم:

```bash
npm run bootstrap
```

إذا لم تُحدد `BOOTSTRAP_PASSWORD` ينشئ السكربت كلمة عشوائية في `.data/bootstrap-credentials.json` بصلاحية 0600، ولا يطبعها. إذا حُددت يجب أن تتكون من 12 حرفًا على الأقل. العملية ترفض إنشاء مشرف ثانٍ؛ استخدم إدارة الصلاحيات بعد ذلك. احذف متغيرات الإقلاع من بيئة الإنتاج بعد إنشاء الحساب. غيّر كلمة التطوير قبل أي تشغيل خارجي.

## الحساب والبريد

الروابط الأساسية: `/auth/register` و`/auth/login` و`/portal` و`/admin`. لوحة الإدارة تتحقق من صلاحيات الحساب على الخادم.

مع `MAIL_MODE=file` في التطوير فقط، تظهر رسائل تأكيد البريد والاستعادة في `.data/mail/`. افتح الرسالة الخاصة محليًا واستخدم رابطها. هذا المجلد ليس صفحة عامة. الإنتاج يرفض البديل المحلي ويتطلب SMTP؛ لا توجد طريقة لتجاوز تأكيد البريد من واجهة الطالب.

`ALLOWED_EMAIL_DOMAIN` يقيد إنشاء الحسابات بنطاق جامعي إذا زوّد النادي النطاق المعتمد. تركه فارغًا يسمح بحسابات ببريد مؤكد ولا يدّعي أنها حسابات جامعية متحققًا منها.

## التحقق

```bash
npm run lint
npm run typecheck
npm test
npm run test:integration
# استخدم Chromium مثبتًا، أو npx playwright install --with-deps chromium
npm run test:browser
npm run build
npm start
```

التكامل والمتصفح ينشئان قواعد اختبار مستقلة مؤقتة ويحذفانها بعد الاختبار، لذلك يحتاج مستخدم PostgreSQL الخاص بالتطوير إلى صلاحية `CREATEDB`. **لا تستخدم حساب قاعدة الإنتاج أو قاعدة مشتركة لتشغيل الاختبارات.** مجلدات `.next-integration` و`.next-browser` منفصلة عن خادم التطوير. `CHROMIUM_PATH` اختياري لاختيار المتصفح. الصور الناتجة من الاختبار في `.data` ولا تُنشر.

## الهيكل

| المجلد | الغرض |
|---|---|
| `app/` | App Router، تصميم النظام، صفحات الخادم وAPI |
| `components/` | الواجهات العامة، الحساب، مساحة الطالب، الإدارة، المختبر الميكانيكي |
| `lib/` | الصلاحيات والجلسات والتحقق والبريد والملفات وعمليات الفعاليات والمعادلات |
| `prisma/` | المخطط والترحيل الأول والبيانات الأولية |
| `scripts/` | إنشاء المشرف، توليد العميل وترحيل قاعدة البيانات |
| `tests/` | اختبارات وحدات وتكامل ومتصفح |

تُخزّن عناوين المحتوى ووصفه بالعربية والإنجليزية في قاعدة البيانات. تستخدم واجهة المنصة ولوحة التحكم خط ثمانية Serif Display بالعربية والإنجليزية بخمسة أوزان محلية بصيغة WOFF2، وتحمّله عبر `next/font/local` دون اعتماد على مزود خطوط خارجي. مصدر الملفات وبصماتها موثّقان في `public/fonts/SOURCE.json`، وتبقى حقوق الخط لثمانية. خط Cairo الخاص بمستندات PDF مرخّص بـOFL ومرفق ترخيصه. شعار النادي الذي أرسله المستخدم موجود في `public/brand/logo.png` ويمكن استبداله بعد اعتماد الهوية من النادي.

## Prisma في البيئات المقيدة

`db:migrate` يستخدم محرك Prisma الرسمي WebAssembly المطابق لمعرّف المحرك في Prisma 7.10.1، ويطبّق ملفات SQL القياسية ويتتبعها في `_prisma_migrations`. هذا يتجنب تنزيل المحرك الأصلي من `binaries.prisma.sh` المحجوب في هذه البيئة. الحزم مثبتة عبر npm مع سلامة lockfile؛ لم يُعطّل TLS أو التحقق من checksums.

`db:generate` يستخدم مخطط WASM المضمّن. يوجّه حلّ مسار المحرك الأصلي غير المستخدم أثناء توليد العميل إلى Node الموجود؛ هذا ليس مسارًا لترحيل البيانات. الترحيل الأصلي الرسمي متاح أيضًا عبر `npm run db:migrate:native` حين يكون مضيف التنزيل مسموحًا. لا تعِد توليد الترحيل الأول بعد تطبيقه. للترحيلات الجديدة استخدم Prisma migrate dev المعتاد في بيئة تسمح بمحركه الأصلي، وراجع SQL ثم اختبره.

راجع [DEPLOYMENT.md](DEPLOYMENT.md) لخيارات Docker وHTTPS وSMTP والنسخ الاحتياطي، و[IMPLEMENTATION.md](IMPLEMENTATION.md) لحالة التنفيذ.

## النشر المؤقت على GitHub Pages

النشر العام الافتراضي الآن يصدر نسخة HTML من التصميم الجديد. من جذر المستودع: `npm run build`، ثم `npm --prefix platform run test:pages`. المحتوى العام في `publication/content.json`، وتفاصيله في README الرئيسي.

`npm run build:pages` داخل هذا المجلد ينتج `.pages-build/out` دون تشغيل الخادم أو قراءة بيانات الطلاب من PostgreSQL. واجهة الحسابات والتسجيل والإدارة المشتركة غير مفعلة في هذا التصدير. يبقى `npm run build` داخل `platform/` مخصصًا للنسخة التي تستخدم خادمًا.
